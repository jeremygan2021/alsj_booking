# 管理后台

入口 `/admin`。管理员账号 `admin` 与旧账号 `gm` 共用现有 GM 密码和权限，没有新增公开默认密码。NPC保持受限权限，登录手机号在NPC编辑页绑定，使用短信验证码，不再密码登录。

## 内容管理中心

| 分类 | 功能 |
| --- | --- |
| 报名资料 | 姓名、手机号/邮箱编辑；搜索；CSV导出；进入原档案进行票务核验、签到、分组 |
| 角色卡 | 完整建立/编辑姓名、英文名、职业、技能、背景、秘密、动机、关联NPC、阵营和审核状态 |
| 线索库 | 新增和编辑编号、标题、区域、分类、技能、DC、开放幕次、基础与进阶证据 |
| NPC档案 | 新增和编辑姓名、英文名、身份、公开背景和GM秘密 |
| 私人委托 | 指定玩家和NPC、新增/编辑任务标题及奖励；结算沿用原任务规则 |
| 拍品与道具 | 新增/编辑起拍价、说明与效果；开放竞拍和落槌仍在拍卖管理页 |
| 广播内容 | 新增及编辑广播；发布和切幕沿用原广播流程 |
| AR场景 | 新增场景、启用/停用、识别图尺寸/序号、模型资源键与坐标、热点半径和关联证据 |
| 报名首页 | 主标题、副标题、英文标题、活动标签、时间说明与简介 |

原有总览、角色审核、金币调整、应急放行、拍卖落槌、庭审投票和名额/价格设置继续保留。新增内容管理API为 `/api/staff/manage`，仅GM角色可访问；管理员显示和编辑保密内容，玩家与NPC不能调用。

已结算委托、已开放或成交拍品不能改写。角色卡编辑不会删除任务、重置金币或收录证据。暂不提供批量删除报名或剧情记录，避免破坏结算和证据关系；AR场景可以停用、移除模型/热点配置。线索编号遵循现有 `E-XX` 规则。

## AR及首页持久化

SQLite与PostgreSQL新增兼容表 `managed_content`，保存运营配置，不改动现有玩家数据。正式AR场景以数据库中的同ID配置覆盖原文件配置；保存后新请求即时生效，正在运行的AR页面须重新进入以获取新版。关闭场景会阻止后续获取/搜证请求。公开体验保持独立，不使用正式场景里的保密证据。

后台只管理资源对象键、坐标和热点映射，没有文件上传或自动制作3D模型功能。GLB与`.mind`文件须先通过部署或OSS上传；改资源域名仍用 `AR_ASSET_BASE_URL`。配置变更后应重新实测标定。所有热点关联证据都开放后，场景才能进入。

## 管理员口令

服务器本机执行 `docker exec alsj-booking node scripts/credentials.js` 可查看现有管理员及全部NPC账号口令；包含后台新增NPC的手机号绑定状态，不显示NPC密码。这个命令只供管理员在可信终端查看，输出不得写进公开日志。

## 验证

`npm test`包含管理员权限、内容新增/编辑、重复编号、联系方式冲突、结算锁定、AR配置及重启持久化。`scripts/admin-browser-test.js`验证后台表单、名单下载、角色卡建立、线索编辑、AR保存、首页生效和移动端布局，写入测试仅允许本机测试站点。PostgreSQL测试使用随机独立schema，不写生产public表。
