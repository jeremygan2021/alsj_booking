# 手机验证码登录与首次自动注册

玩家默认入口使用手机号验证码，首次成功验证后自动创建报名档案；已有相同手机号直接登录，姓名和原角色、金币、票务不被覆盖。不填写称呼时生成“宾客+手机号后四位”。新报名仍须付款核验、签到、角色审批。报名容量限制只影响新账号，满额时已有账号仍可登录。

玩家与NPC仅使用手机验证码；仅管理员admin/gm保留密码登录。NPC登录手机号在后台内容管理中心的NPC编辑页绑定，不对外公开。旧密码入口和公开密码注册接口已关闭；已有邮箱账号需由管理员改为实际手机号后才能验证码登录。登录前的线索和AR场景链接继续保留。

## 阿里云配置

- 服务：短信服务 Dysmsapi，`SendSms`，官方 `@alicloud/pop-core` SDK。
- 端点：`https://dysmsapi.aliyuncs.com`。
- 模板：`SMS_493295002`，变量`code`，六位数字，有效期15分钟。
- 签名：`叠加态科技云南`，已通过查询接口确认审核通过。
- 凭据和短信签名仅配置在服务器 `/var/lib/alsj_booking/.env`，不进入前端、代码或发布包。

```text
SMS_ENABLED=true
SMS_TEMPLATE_CODE=SMS_493295002
SMS_SIGN_NAME=叠加态科技云南
ALIBABA_CLOUD_ACCESS_KEY_ID=<服务端凭据>
ALIBABA_CLOUD_ACCESS_KEY_SECRET=<服务端凭据>
SMS_CODE_SECRET=<独立随机密钥>
```

未启用短信时普通用户无法登录，不回退到密码。声明启用但缺少配置会阻止服务启动，避免对外声称短信可用。

## 接口与校验

`POST /api/auth/sms/send`接收`phone`，返回有效期与重发等待时间，不返回验证码。

`POST /api/auth/sms/login`接收`phone`、`code`以及可选`name`；返回`registered`说明是否首次报名，并设置原有HttpOnly会话Cookie。

验证码采用加密随机生成，只保存绑定挑战ID和手机号的HMAC摘要。发送请求预先在数据库事务中占用额度，发送成功后激活；供应商失败不会激活验证码。短信网络请求在事务外执行，不长时间锁定玩法数据库。验证失败次数持久化，五次失败后锁定，成功验证码一次使用，成功重发使旧码失效。

手机号60秒内只能请求一次，每小时最多5次、每天10次；同IP每小时最多10次；全站每天最多200次。使用持久化数据库计数，适用于多实例。IP使用HMAC保存，过期请求记录两天后清理。发送失败也计入额度，避免反复调用供应商。

## 测试与运维

`tests/sms.test.js`覆盖自动注册、已有账号、容量、重发、过期、错误锁定、并发、供应商失败和密码登录拒绝。`scripts/sms-browser-test.js`启动独立内存测试站点并注入短信发送器，验证首次注册/老账号登录、线索跳转、手机号唯一入口及管理员入口；不发送真实短信。

真实送达另行用授权测试手机号验证。供应商返回OK表示受理，不等同于手机收到短信。短信发送异常只记录供应商错误码，不记录手机号、验证码或供应商请求对象。尚未接入短信送达回执。

## 测试验证码

开发快速登录：运行 `npm run dev:quick-login`，所有手机号直接输入188888，无需阿里云配置或发送短信。已绑定NPC的号码进入对应NPC工作台，其他号码注册/登录玩家账号；不授予管理员权限。页面明确显示开发测试模式。此开关只允许development/test环境，生产环境或安全Cookie部署尝试启用时直接拒绝启动。

固定测试码188888仅对服务端配置的SMS_TEST_PHONE生效，需配置SMS_TEST_EXPIRES_AT到期时间；默认关闭，不对其他手机号生效，也不会授予管理员权限。本次指定测试手机号，启用24小时，之后使用正常短信。测试模式不调用短信供应商，正常发送与测试码验收分别进行。
