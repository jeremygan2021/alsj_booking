# MiniMax角色生成与现场演绎

## 玩家角色

`/play` 的“我的角色”提供“MiniMax生成头像、姓名与故事”。可以先填写Cos角色、来源、灵感，也可以留空生成原创宾客。服务端使用 `MiniMax-M2.5` 创作姓名、职业、动机、故事与2–3位NPC的往事，使用 `image-01` 生成头像。模型只收到公开背景、公开NPC档案与玩家填写的角色素材，不接收手机号、GM私稿、证据秘密或真实阵营。

结果先填入可修改的草稿，不自动提交审批。用户确认后提交，沿用原有NPC关联与GM审核；未改动的生成稿复用已校验的NPC关联，避免再次调用文本模型。角色头像、原始故事和关联档案可在GM的“宾客与角色”中查看。NPC只能看到GM批准后与自己关联的人物。

`POST /api/character/inspire` 要求玩家登录，接收可选 `cosplay_character`、`cosplay_source`、`idea`，只返回角色字段与私有头像URL。头像经尺寸限制、解码及WebP重编码后保存到原头像表。文本或图片失败不会覆盖旧头像、角色与表单输入。单玩家同一时间只运行一次，最多每分钟3次，与原角色关联接口共用次数限制；单实例最多2个完整角色任务。生成期间角色被提交、批准或头像被另页修改时，拒绝写入迟到结果。

在服务器持久化环境文件配置：

```dotenv
MINIMAX_API_KEY=服务端密钥
MINIMAX_BASE_URL=https://api.minimax.cn/v1
MINIMAX_TEXT_MODEL=MiniMax-M2.5
MINIMAX_IMAGE_MODEL=image-01
```

没有单独配置LLM时，提交后的NPC关系生成也使用MiniMax。若沿用已设置的LLM参数，统一填写MiniMax地址、同一密钥、`MiniMax-M2.5`，并设置 `LLM_RESPONSE_FORMAT=none`。所有JSON仍经过服务端字段、NPC白名单、剧情边界与长度校验。`reasoning_split` 将推理与最终JSON分开。配置不会由公开接口返回。

文本与生图依次调用，各自最长90秒；Nginx网站代理应设置 `proxy_read_timeout 210s`。现有 `/echo/` 独立代理配置应保留。

## GM现场播放

`/admin` → “现场演绎音频”提供更新交付包的14段已制作成片，共22分43秒。包含背景、万圣节暖场、六人登场、撒钱开场、拍卖、21:07声音、发现尸体、瑟琳娜回忆、证言交锋、时间校准、庭审、行凶重建、遗言与结尾。A10/A11/A12收在默认折叠的终局区。

原音频由MiniMax `speech-2.8-hd` 制作；本次复用交付包已核验的MP3，不重复提交付费语音任务。8组角色音色固定：索恩真人、ECHO演示与遗言使用同一沉稳高管音色；其余角色分别绑定原音色ID、速度和音高。清单可在播放台展开查看。

每段已包含背景配乐与音效，点播放器才开始加载播放；播放新段会暂停上一段。支持暂停、跳转、音量、下载MP3、全部暂停、环节筛选与舞台cue。离开页面释放媒体。终局前须根据主持执行手册判断释放时机；21:07声音不能当作真实行凶时刻。

清单位于 `server/audio/performance-audio.json`，成片位于 `server/audio/performance-files/`。两者随应用发布，不放入前端静态目录。`GET /api/staff/performance-audio` 及 `/:id/file` 均只允许GM；支持Range/HEAD及 `private,no-store`，玩家、NPC和游客无法下载。清单返回舞台摘要，不返回完整私稿、文件系统路径或密钥。

配乐为Kevin MacLeod作品，CC BY 4.0；音效为Kenney，CC0。播放器保留来源与混音署名。完整分轨、全台词和动作时间轴继续保留在本机原交付包，供GM离线使用。

## 验证

模块测试覆盖结构校验、角色边界、模型协议、失败恢复、头像格式与文件路径；实际应用路由测试覆盖登录、GM隔离、批准锁定、并发、迟到结果及限流。浏览器测试覆盖生成失败保留/重试、草稿人工提交、真MP3互斥播放、终局折叠、退出停播与手机布局。

生产发布沿用 `deployment/update-ar.sh`：先备份PostgreSQL，再发布含全部私有音频的应用镜像；不重建数据库，也不调整ECHO独立服务。
