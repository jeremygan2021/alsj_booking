# 三阵营偏好、抽签与接头暗号

本场最多50位玩家。新旧报名接口均有50人硬上限，满额后已有玩家仍可登录；GM只能把名额调低，不能设为51或更多。升级将本场原40人配置一次调整为50，保留全部账号、角色和游戏记录；后续重启不会恢复GM主动调低的容量。

## 玩家流程

创建角色前，玩家选择FBI调查阵营、索恩遗产阵营、杀手阵营或服从安排。页面提前说明：杀手偏好只代表参加抽签，不保证入选。已保存的老角色仍可查看，也能在档案上方补选偏好。

只有已付费、角色已批准且保存了偏好的玩家参加本轮抽签，NPC绑定账号不计入玩家名单。未选偏好的人在GM页面明确提示，不会默认为愿意扮演杀手。

杀手席位为 `clamp(round(确认参与人数 / 12), 2, 5)`：40人时3名、50人时4名。至少4位玩家才能确保三个阵营都有成员。优先从选择杀手的人中随机抽取，不足时从服从安排者补足；候选人数不足则拒绝抽签，提醒GM征集自愿者。其余玩家在两个非杀手阵营之间人数差不超过1人，并尽量兼顾偏好。

杀手本人获知自己属于杀手阵营，以及真正凶手的身份；须在活动开始前找到凶手，说出本人随机生成的接头暗号。杀手是协助真凶的同伙，不改变NPC作为唯一致命袭击实施者的案件设定。其他玩家无法读取凶手简报、他人的暗号或完整分配名单。

## GM操作

`/admin` → “阵营与暗号”：核对名单、候选数和预计席位，再手动确认抽签。系统不会在部署、报名或生成角色时自动抽签。

每人暗号独立、随机、唯一，保存到数据库；刷新和重启不会变化。GM可查看和复制全部杀手的暗号，角色详情也可查看对应玩家的偏好与私密身份。普通NPC账号没有此入口或读取权限。

抽签完成后本轮不能重抽，已经分配的玩家不能改偏好。晚加入但尚未分配的玩家仍可填写偏好，由GM补位；调整须遵守本轮冻结席位、杀手至少2人及其他两营人数差不超过1人的规则。明确选择非杀手阵营的玩家不能被强制改为杀手。

## 实现与权限

- `faction_preferences`保存意愿，`faction_assignments`保存正式身份与暗号，`faction_draw_state`记录唯一一轮抽签；迁移不自动覆盖旧角色身份。
- `/api/me`只返回当前玩家的阵营状态；偏好接口只使用当前会话身份，不接受替别人选偏好。
- `/api/staff/factions`、`/draw`和`/:id`仅GM可用。私密响应使用`private,no-store`，审计不写暗号明文。
- 使用加密随机源抽签与生成暗号；事务保证并发抽签只完成一次，失败全部回滚。SQLite与PostgreSQL沿用同一规则。
- GM旧角色编辑接口复用同一约束，无法通过另一个入口绕过抽签或人数限制。

阵营轻量任务与这套抽签和接头规则并行，不改变私密身份与知情范围。
