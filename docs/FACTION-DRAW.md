# 创建时确定阵营与私密接头

本场最多50位玩家。新旧报名接口均有50人硬上限，满额后已有玩家仍可登录；GM只能把名额调低，不能设为51或更多。升级将本场原40人配置一次调整为50，保留全部账号、角色和游戏记录；后续重启不会恢复GM主动调低的容量。

## 玩家流程

创建角色时，玩家选择FBI调查阵营、索恩遗产阵营、杀手阵营或服从安排。默认新场次在保存创建意向时确定正式阵营；首次生成或提交角色也会补充分配。杀手意向不保证入选，明确选择非杀手的玩家不会被强制分配为杀手。已保存的老角色仍可查看，也能在档案上方补选意向。

正式阵营在创建流程即可查看，重新生成角色、模型失败、刷新或服务重启都不会重抽。已确定身份后意向锁定，需要变更时由GM按本轮席位规则调整。未保存意向就直接生成或提交时，系统按“服从安排”处理；NPC绑定账号不参与宾客分配。

本轮首次创建分配时，按活动容量冻结杀手席位：`clamp(round(活动容量 / 12), 2, 5)`，40人容量为3席、50人容量为4席。明确选择杀手且仍有席位时可获分配；服从安排者按剩余席位抽取。其余玩家在两个非杀手阵营之间保持人数差不超过1人，并尽量兼顾意向。创建中人数较少时尚未用满全部席位属于正常情况；后续不会因重生成而抢占或重新抽取身份。

杀手本人先获知自己的正式阵营；本人已付费且角色获GM批准后，才开放私密接头简报、目标和本人随机暗号。活动开始前先找GM私下核验，由GM安排本次联络交接。杀手是协助真凶的同伙，不改变NPC作为唯一致命袭击实施者的案件设定，也不自动获得袭击时间、物证关联或完整答案。其他玩家无法读取凶手简报、他人的暗号或完整分配名单。

## GM操作

`/admin` → “阵营与暗号”：查看创建流程已经确定的正式身份、本轮冻结席位及未分配者，按需处理异常或补位。默认新场次不需要再点击批量抽签；已有正式分配不能整轮重抽。仅显式启用旧场次兼容模式时，沿用“已付费、角色已批准且保存偏好后，由GM手动抽签”的旧流程。

每人暗号独立、随机、唯一，保存到数据库；刷新和重启不会变化。GM可查看和复制全部杀手的暗号，角色详情也可查看对应玩家的意向与身份。普通NPC账号没有完整名单或暗号管理入口。名单只用于GM私下核验，不展示给其他玩家或整组演员。

接头按四步执行：玩家向GM出示本人的私密页面；GM核对本人身份与该人的完整暗号；GM私下向目标演员交接“本次联络已核验”；演员只照读固定联络确认。演员无需背诵或比对16字暗号，也不接收完整名单或他人暗号。未经GM确认时，演员只说“请先找GM完成私下核验”，不泄露案情或额外身份信息。

创建模式下的后续补位和单人调整不得超过本轮冻结的杀手上限，其他两营人数差不得超过1人；明确选择非杀手的玩家不能被强制改为杀手。旧场次手动抽签模式继续要求杀手至少2人。所有已分配身份都保持稳定，不因角色重生成改变。

调查互动同样由GM接手判断：玩家陈述，GM核对已开放证据及当前阶段，GM给出口令，演员照读固定段。完整推论和供认门槛由GM核对，不能只按卡数或投票触发供认；演员不负责裁判推理、临场补案情或决定证据权限。

## 实现与权限

- `faction_preferences`保存意愿，`faction_assignments`保存正式身份与暗号，`faction_draw_state`记录本轮模式与冻结席位；迁移不自动覆盖旧角色身份。
- `/api/me`只返回当前玩家的阵营状态；偏好接口只使用当前会话身份，不接受替别人选偏好。
- `/api/staff/factions`、`/draw`和`/:id`仅GM可用。私密响应使用`private,no-store`，审计不写暗号明文。
- 使用加密随机源分配与生成暗号；事务保证并发创建不会超占席位，同一玩家不会重抽，失败全部回滚。SQLite与PostgreSQL沿用同一规则。
- GM旧角色编辑接口复用同一约束，无法通过另一个入口绕过抽签或人数限制。

阵营轻量任务与这套分配和接头规则并行，不改变案件真相、证据权限、私密身份或知情范围。
