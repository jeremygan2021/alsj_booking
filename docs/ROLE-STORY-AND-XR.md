# Cos 角色、NPC 剧情关联与 AR / VR

## 玩家流程

1. 报名并登录 `/play`，填写万圣节准备 Cos 的角色、作品或原创来源、头像和角色故事。姓名、英文名、职业、技能和赴宴动机在「补充设定（可选）」中，不填也能提交。
2. 系统保留玩家原文，另外生成适配 2026 年 ECHO 庄园世界的背景。原作中的能力、身份和装备被转为人物气质、现实职业、道具或个人目标，不能改变四幕剧情的主线事实。
3. 为角色生成 2–3 位 NPC 联系人，每位包含关系、玩家说明、NPC 演绎说明、分幕目标和一项破冰任务。任务奖励固定为系统规则中的 2 金币，模型没有奖励或阵营决定权。
4. GM 在宾客管理中查看原故事和生成草稿，确认身份与剧情可执行后批准。玩家能预览自己的关系草稿，NPC 只有批准后才能看到与自己有关的玩家。
5. NPC 登录 `/admin` 的「关联玩家」，通过头像识别宾客，阅读 Cos 设定、双方关系、自己应该如何演绎以及不同幕次的互动目标。

## 关联设计

关系围绕公开 NPC 功能建立，避免所有玩家只按技能联系同一位 NPC：

| NPC | 合理关联方向 | 现场互动 |
| --- | --- | --- |
| 盖茨比 | 受资助者、旧友、投资对象、受邀创作者 | 财富挑战与赴宴邀请 |
| 黛西 | 情感、身份、记忆、艺术与人机关系 | 默契游戏与观点交换 |
| 维拉 | 商业谈判、债务、交易、投资竞争 | 交换筹码与拍卖沟通 |
| FBI 探员 | 正义、调查、记者、旧案线索 | 谎言测试与公开信息交叉验证 |
| 保镖 | 安全、护卫、接头、受保护人 | 接头暗号与现场协作 |
| AI 研究员 | 技术、记忆研究、数据、人工智能 | AI 游戏与鉴定协助 |

例如 Cos 蝙蝠侠的玩家可以保留追求正义、调查能力和失去亲人的故事主题，在庄园世界中扮演受邀的独立调查者；与 FBI 探员形成情报合作，与保镖形成安全流程上的信任冲突。系统不会赋予超能力、现场伤害行为或直接知道凶手的权利。具体生成结果仍由 GM 审核。

## 大模型配置

把以下项目写入服务端 `.env`，再重启服务。密钥只在服务器使用，不会进入前端或 `/api/public`。

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=填写你自己的服务端密钥
LLM_MODEL=填写服务商实际支持的模型名
LLM_RESPONSE_FORMAT=json_schema
```

`LLM_BASE_URL` 是包含 `/v1` 等前缀的 API 基地址，服务端在其后调用 `/chat/completions`。其他兼容服务使用各自地址和模型名。若服务商不支持 JSON Schema，显式设置 `LLM_RESPONSE_FORMAT=json_object`；两种模式都会再次通过服务端字段、NPC 白名单和长度校验，不会自动降级重试并重复产生费用。

结构化输出实现参考 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。发送给模型的是玩家填写的角色文本、NPC 公开档案和公开剧情约束；不发送玩家联系方式、密码、头像、GM 秘密、证据正文或真实阵营。

未配置接口时，明确显示「模板草稿」，可以体验完整的审核和双向关系流程。配置了接口但请求失败时，保留玩家输入并显示失败状态，可重试；不会把失败结果冒充大模型生成。网络生成不持有游戏数据库事务，写入结果时校验角色版本，防止旧请求覆盖新的故事。

已批准档案保持锁定；若配置模型后需要替换之前的模板关系，GM 先把角色退回待审核，玩家再生成并重新提交，避免活动中途悄悄改变演员的任务。

## 两个探索入口

### AR 搜证

独立入口 `/ar` 面向现场扫码使用，无需注册或登录。默认按钮直接进入全屏相机，持续追踪现场二维码四角，把证物模型贴在二维码所在的墙面或桌面，跟随位置、旋转、大小和透视；丢码时隐藏，重新对准即恢复。文字线索在相机内展开，360°预览、二维码图片和编号阅读收在次要入口。后台生成 `/ar?clue=E-01` 形式的二维码，系统扫一扫可预载对应线索，点击开启相机后对准原码进行 AR。页面不预先展示全部线索列表，也不为匿名用户写入证据册。详见 [二维码追踪约定与验证](QR-TRACKING.md)。

公开接口 `/api/ar/clues/:id` 只返回编号、标题、地点、类别、基础正文及模型地址；不返回进阶信息、检定结果或人物数据，不受活动阶段限制。`/api/ar/models/:filename` 只提供与有效线索关联的三类白名单示例 GLB。游戏内资格与阶段规则继续用于个人进阶检定、解锁记录和证据册。

次要 360°查看器仍可调用原生 AR，参考 [model-viewer 官方示例](https://modelviewer.dev/examples/augmentedreality/) 与 [Scene Viewer 文档](https://developers.google.com/ar/develop/scene-viewer)。原生查看器使用公开 HTTPS 模型地址，不依赖玩家 Cookie；它不承担默认二维码锚定模式。

「沉浸搜证」提供可环绕观察的独立场景，标题、编号和地点均绘制为 3D 场景文字；定位环、扫描光带与粒子在模型旁显示。支持 WebXR 的手机可在场景内点击「进入现实 AR」，寻找平面后放置模型和文字。Android/iPhone 原生查看器继续通过「放到现实中」打开模型，不包含自定义场景文字。等待 AR 授权时切后台会取消这次启动并恢复可重试状态；关闭场景会中止加载、结束 XR 并释放画布资源。

音乐由浏览器本地合成，在用户操作后启动，可暂停和调节音量；切后台暂停，离开页面释放。GM 在 `/admin` 的「证据与二维码」可下载全部线索 PNG 的 ZIP 和 A4 可打印清单，或单张 PNG。下载仅包含编号、标题、地点和公开线索链接，不打包进阶正文。

玩家页只保留「我的角色」「AR搜证」「证据册」三个常用入口；提交后直接看到等待GM确认的摘要，现场签到后按当前幕次给下一步提示。拍卖、庭审和完整关系详情收在次要区域。

点击「AR 搜证」→ 全屏后置相机持续追踪二维码并显示公开基础模型 → 满足票务、签到、角色批准和当前阶段条件的玩家同步解锁个人证据册 → 退出相机后从证据册查看私人信息、检定或 360°模型。

二维码本身承担持续视觉定位，默认模式不需要 WebXR 或另印定位海报。相机需要安全上下文（生产 HTTPS）和设备授权；二维码需保持在镜头内，不使用丢码后的环境建图锚点。关闭、切后台或返回时停止相机并释放资源。没有相机权限时仍可输入编号阅读或查看 360°模型。

### VR · 360°鉴赏

在「证据册」点击次要按钮「360°查看证物」，列出已经解锁的证物，可以选择模型、查看证据、360°旋转、缩放和全屏。头显操作收在默认关闭的「使用VR头显（可选）」中，展开才加载 VR 渲染器；支持 WebXR 的头显浏览器可进入沉浸式 VR。当前交付的是证物模型鉴赏，不是实景庄园的 360°全景照片，也不是多人虚拟庄园。没有已解锁证物时，界面提示先搜证。

模型仅包含道具外观，不含凶手、证据正文或鉴定结果。三组剧情示例资源如下，十二张证据按类别复用：

| 模型 | 证据编号 |
| --- | --- |
| 封蜡信件 / 遗嘱 | E-01、E-03、E-07、E-10、E-12 |
| ECHO 技术终端 | E-02、E-04、E-05、E-08、E-11 |
| 物证箱 | E-06、E-09 |

资源在 `public/models/*.glb`，映射在 `src/evidence-models.js`；可以按证据更换独立 GLB。需要维持映射与服务端资源白名单一致。独立扫码页读取公开 `/api/ar/models`；游戏内查看器读取 `/api/models`，该接口继续要求玩家资格和对应证据解锁。Vite 不公开整个模型目录，生产构建也不复制它到 `dist`，两种读取入口均由服务器限定文件名。

## 运维与验证边界

数据库迁移是增量迁移：保留旧角色、金币、任务、竞拍、证据与工作人员编辑；旧角色的已有 NPC 联系人迁入关系表。头像被服务端解码、限制尺寸并重新编码为 WebP，存入数据库；仅本人、GM 和已获批准关系的对应 NPC 能读取。

运行 `npm test` 和 `npm run build` 验证规则、生成请求与构建。`npm run test:browser` 使用独立内存数据库和默认 3301 端口（可用 `ALSJ_BROWSER_TEST_PORT` 调整），验证上传、角色草稿、GM审核、NPC关系、匿名二维码识别、音乐、场景加载/清理/重试、AR 授权恢复与下载包，不写入日常开发数据。需要 Playwright Chromium；若使用已安装的 Chrome，可设置 `CHROMIUM_EXECUTABLE_PATH=/path/to/chrome`。

正式举办前还要用目标 Android 手机 / VR 头显的实际浏览器测试安全域名、扫码、AR 放置、VR 进入退出和模型性能。桌面 3D 预览通过不代表真机 WebXR 验证通过。当前大模型测试使用模拟兼容服务验证协议、结构校验与错误恢复，真实服务验证需要自己的模型名、接口地址及密钥；PostgreSQL 集成测试需要独立配置 `TEST_DATABASE_URL`，运行器与角色测试各自使用随机独立 schema，完成后清理，不读写生产 public 表。
