# 二维码锚定搜证

玩家打开 `/ar`，点击全屏扫码，允许后置相机，再对准现场二维码。无需登录。识别到对应证据后，模型直接贴在二维码所在平面，随二维码在画面中的位置、旋转、大小和透视变化。墙上的二维码定义墙面，桌上的二维码定义桌面。短暂掉帧不会立刻隐藏模型；持续失去可靠定位时淡出，重新对准即可恢复；扫描另一张有效码会切换证物。文字线索通过相机内的按钮展开。轻触模型或底部动作按钮，可以拆封信件、启动终端、打开物证箱，再次点击可收起。动画不改变剧情进度，也不额外揭示私人信息。

二维码必须保持在画面中。这是连续视觉锚定，不会在丢码后依靠手机环境建图继续留住模型。建议把二维码平整打印在哑光纸上，贴在证物展示的位置；二维码应有白色边距、光照均匀，避免反光、折痕和遮挡。已有 `/ar?clue=E-xx` 和本站旧 `/play?clue=E-xx` 码均可使用。无需另印定位海报或编译 `.mind`。

## 定位与模型约定

`jsQR` 约每 110 ms 从原始视频帧确认编号和四角；两次解码之间，`jsfeat` 金字塔 Lucas–Kanade 光流追踪最多 81 个码面特征点。前后向误差检查、RANSAC 平面拟合、最少特征数和分布跨度过滤遮挡与误匹配，最长 650 ms 必须重新解码确认。小幅角点噪声按时间平滑，大幅运动立即跟随。`qr-pose.js` 估计平面姿态，再用 Three.js 渲染透明模型层。相机视频的 `object-fit: cover` 裁剪和渲染相机使用同一套比例，避免手机竖屏时漂移。二维码定义局部 XY 平面，边长为一单位，+Z 朝纸面外。GLB 按 Y-up 导入，转换为底面贴 QR 平面，模型高度朝 +Z，比例相对二维码设置。终端朝外倾斜陈列，以便看到屏幕。深绿金边底板覆盖 1.48 倍二维码边长，包含标准四模块白边；它与模型共享同一透视锚点。原始视频参与追踪，虚拟遮盖不会挡住算法识别。没有自动旋转或用户拖动定位。

首次定位用 260 ms 渐显；追踪失败后保留 140 ms，再用 130 ms 淡出。短暂掉帧可恢复原显示，不重复播放出现动画。动画独立于相机帧率更新。只有可靠定位且模型已呈现时接受射线命中的点击；拖动、点击空白墙面和丢码后的点击不触发。保留键盘可用的动作按钮，并支持系统减少动态效果设置。

`qr-evidence-presentation.js` 为现有 GLB 命名部件添加运行时铰链动画：信封开口、蜡封移开、信纸展开；终端屏幕与指示灯点亮、信号流动、按键响应；箱盖绕铰链开合。GLB 原文件和次要 360°查看器保持原有行为。

二维码提供相对尺度，当前未标定每台手机的镜头畸变或真实焦距，也未要求输入二维码的实际厘米尺寸。因此测量结果不能当作现场物证的厘米尺寸。要做墙上弹孔，可替换对应 GLB 为底面贴墙、厚度向外的弹孔模型；现有剧情证据仍使用既有模型和正文。

相机要求 HTTPS（开发 localhost 也可）。支持 Fullscreen API 时进入浏览器全屏；不支持的手机使用覆盖整个视口的相机页面。关闭、返回、切后台或卸载时停止相机轨道并释放渲染资源。拒绝权限时提供重试；360°预览和编号/图片阅读可独立使用。

## 验证

`tests/qr-pose.test.js` 用已知三维姿态投影的四角验证平移、旋转、倾斜、尺度及异常几何。`tests/browser/qr-tracking.spec.js` 使用真实二维码像素生成相机视频，经过实际解码、姿态计算和渲染，验证手机裁剪对齐、连续移动、丢码/恢复、换码与相机回收。`tests/qr-frame-tracker.test.js` 使用真实二维码像素验证帧间移动、定位角遮挡、空白墙拒识和超时；`tests/qr-evidence-presentation.test.js` 载入实际 GLB 验证底板遮盖范围、部件变换及可逆动画。浏览器测试还验证真实模型点击、空白区域不响应、短暂失帧不闪烁和三种互动。自动测试不替代真实手机在反光、弱光、快速移动和不同镜头下的现场验收。

公开追踪只读 `/api/ar/clues/:id` 和公开模型，不写入玩家证据册。登录玩家仍须满足票务、签到、角色批准和阶段条件才记录个人解锁，进阶正文和检定仍保留原有权限。
