# 二维码锚定搜证

玩家打开 `/ar`，点击全屏扫码，允许后置相机，再对准现场二维码。无需登录。识别到对应证据后，模型直接贴在二维码所在平面，随二维码在画面中的位置、旋转、大小和透视变化。墙上的二维码定义墙面，桌上的二维码定义桌面。二维码离开画面或不能可靠定位时隐藏模型，重新对准即可恢复；扫描另一张有效码会切换证物。文字线索通过相机内的按钮展开。

二维码必须保持在画面中。这是连续视觉锚定，不会在丢码后依靠手机环境建图继续留住模型。建议把二维码平整打印在哑光纸上，贴在证物展示的位置；二维码应有白色边距、光照均匀，避免反光、折痕和遮挡。已有 `/ar?clue=E-xx` 和本站旧 `/play?clue=E-xx` 码均可使用。无需另印定位海报或编译 `.mind`。

## 定位与模型约定

`jsQR` 从原始视频帧解码并返回四角，`qr-pose.js` 估计平面姿态，再用 Three.js 渲染透明模型层。相机视频的 `object-fit: cover` 裁剪和渲染相机使用同一套比例，避免手机竖屏时漂移。二维码定义局部 XY 平面，边长为一单位，+Z 朝纸面外。GLB 按 Y-up 导入，转换为底面贴 QR 平面，模型高度朝 +Z，比例相对二维码设置；没有自动旋转或用户拖动定位。

二维码提供相对尺度，当前未标定每台手机的镜头畸变或真实焦距，也未要求输入二维码的实际厘米尺寸。因此测量结果不能当作现场物证的厘米尺寸。要做墙上弹孔，可替换对应 GLB 为底面贴墙、厚度向外的弹孔模型；现有剧情证据仍使用既有模型和正文。

相机要求 HTTPS（开发 localhost 也可）。支持 Fullscreen API 时进入浏览器全屏；不支持的手机使用覆盖整个视口的相机页面。关闭、返回、切后台或卸载时停止相机轨道并释放渲染资源。拒绝权限时提供重试；360°预览和编号/图片阅读可独立使用。

## 验证

`tests/qr-pose.test.js` 用已知三维姿态投影的四角验证平移、旋转、倾斜、尺度及异常几何。`tests/browser/qr-tracking.spec.js` 使用真实二维码像素生成相机视频，经过实际解码、姿态计算和渲染，验证手机裁剪对齐、连续移动、丢码/恢复、换码与相机回收。自动测试不替代真实手机在反光、弱光、快速移动和不同镜头下的现场验收。

公开追踪只读 `/api/ar/clues/:id` 和公开模型，不写入玩家证据册。登录玩家仍须满足票务、签到、角色批准和阶段条件才记录个人解锁，进阶正文和检定仍保留原有权限。
