# 网页版 VR 是否必要

评估日期：2026-10-08。当前产品是单场40人现场 TRPG，核心为 NPC 演绎、社交任务、实体线索搜证、竞拍与庭审。建议先上线稳定的手机扫码、翻牌和证据册，暂不把头显 VR 作为报名或游戏的必需入口。

## 三种方案

| 方案                      | 帮助                                                                        | 代价与限制                                                                         | 建议                               |
| ------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------- |
| 普通网页扫码 + 3D翻牌动效 | 现场线索直接进入私人证据册，保留演员互动和实体搜证                          | 相机需要HTTPS和授权；提供图片识别与编号备用入口                                    | 当前采用                           |
| 360°全景网页 + 点击热点   | 远程玩家可以浏览书房、大厅、安保室、档案室并调查线索；电脑/手机鼠标触摸操作 | 要准备全景素材、设计热点、控制图片大小、适配手机；仍需角色与阶段权限               | 有远程游戏需求时先做一个场景试点   |
| 头显 WebXR VR             | 可在虚拟空间中看场景、操作道具，适合明确的沉浸体验产品                      | 需要支持的浏览器和设备、3D素材、交互和性能调优；现场还涉及头显轮换、卫生和操作教学 | 有明确付费需求及设备后再做可选模式 |

翻牌使用 CSS 3D 变换，属于网页动效，不需要3D引擎、头显或WebXR。当前二维码识别库按需加载，摄像头画面仅在客户端处理，服务器仍处理鉴权与游戏规则。

WebXR可以提供浏览器中的VR/AR会话，但兼容性仍有限，需要安全上下文，实际设备支持应通过运行时检测验证，不能仅凭“网页能打开”判断VR可用。[MDN：WebXR Device API](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API)、[MDN：isSessionSupported](https://developer.mozilla.org/en-US/docs/Web/API/XRSystem/isSessionSupported)。

摄像头扫码依赖 `getUserMedia`，需要HTTPS/localhost与用户授权，因此提供其他入口。[MDN：getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。二维码识别采用独立JavaScript库，避免只依赖兼容性有限的原生BarcodeDetector。[jsQR官方说明](https://github.com/cozmo/jsQR)、[MDN：Barcode Detection API](https://developer.mozilla.org/en-US/docs/Web/API/Barcode_Detection_API)。

## 为什么现在不优先开发头显 VR

这是基于当前玩法的产品判断：玩家已有真实庄园区域、NPC和实体证物可互动；头显增加的收益尚未证明，而设备引导会分散社交和现场节奏。全场虚拟化还需要单独设计移动、拾取、人物交互、空间信息及多人状态同步，不能只为“扫码翻牌”增加整套VR开发。

资源方面，二维码识别与翻牌在玩家设备上完成。未来全景/WebXR可沿用现有服务端权限、剧情阶段和证据解锁接口；不要把证据正文直接藏在公共场景资源或3D模型里。需要扩大资源分发时再采用图片分级加载、对象存储/CDN。

## 何时值得推进

1. 确定要提供远程参与，远程用户无法接触实体场景。
2. 已有可用的全景照片或3D场景素材，且有真实体验需求。
3. 若采用头显，明确支持的设备、浏览器、控制器及现场设备维护方式。
4. 先做一个房间、三处热点、一次搜证的小原型，比较完成率、加载时间、玩家反馈和运营收益；通过后再扩大。

推荐路线：当前手机扫码与翻牌 → 远程需求下的360°场景热点 → 有设备与素材条件时的可选WebXR。扫码、手动输入和证据册始终保留，让兼容性不足的设备仍可参与。
