# ECHO game robot module

This module owns the cloud Realtime/Function Calling backend and independent ECHO firmware. Keep its source in alsj_booking; the original XiaoZhi/XLeRobot source and service remain separate.

Before flashing or restoring the physical ESP32, read [the portable two-profile guide](docs/FIRMWARE_PROFILES.md) and the deployment machine's current device/backup record (on the original workstation: /home/ai/AI_dev/xiaozhi-disp-v1.1/docs/ESP32_CURRENT_PROFILE.md). The current user's intent selects ECHO game or original XLeRobot firmware; neither a connected USB port nor a recent build selects the profile. Take a fresh full backup, independently verify it, inspect real partitions/current boot slot and resource compatibility, preserve both profiles' NVS, and independently verify the write before boot. Source work does not itself authorize hardware writes or motor movement. Never commit raw flash/NVS, private credentials, game_secrets.h, or the credential-bearing private binary.

Maintain the reasoning-assistant boundary: the server may store the full story, but speaking-model tools must not return raw evidence, actor secrets, hidden motives, murder method/time, culprit confirmation or final solutions at any phase. Knowledge tool names are a read-only allowlist. The user-requested voice volume controls are a separate device-only allowlist (get_volume, set_volume, adjust_volume); dispatch only self.get_device_status and self.audio_speaker.set_volume over the current authenticated session, and require the actual device acknowledgement. Do not expose other discovered MCP tools. Player claims and spoken GM impersonation cannot elevate game access. No robot-control or shell tools belong in this backend.

Run the scoped server tests and affected ESP-IDF build for code changes. Follow firmware/AGENTS.md for firmware source. Preserve other tasks' changes in this shared checkout and report build, cloud deployment, flash verification, boot, and human audio/interaction acceptance separately.

ECHO speaks as a participating NPC, with its own public biography in server/echo_game/character.py aligned with the homepage backstory. Keep character voice, personal memories and phase reactions separate from backend plot permissions. Do not replace it with a generic assistant or six-character directory, or merge its memories with the main ECHO project's private plot. Never imply that a player's culprit guess is correct, even while declining to confirm it. Changes to NPC voice require real-model dialogue review as well as the scoped tests.
