# 配套系统开发需求说明

版本：1.0｜依据：用户提供的剧本设计稿｜定位：技术评估及排期输入。**现有网站后台未核实；下述字段与功能均为建议实现方案，不代表系统当前具备。**

## 1. 项目目标

支持30—40名玩家、6名NPC的沉浸式调查。系统管理证据解锁、VR热点、二维码AR验尸、NPC证言、主持人调度、庭审提交。纸质备份必须能在网络或AR失效时支撑完整推理。

## 2. 角色与权限

| 角色 | 权限 |
|---|---|
| 玩家/小组 | 扫码、读已解锁内容、提交庭审答案 |
| NPC | 查看本人可知事实与证言阶段 |
| GM | 查看全局真相、推进阶段、解锁保底证据、看进度 |
| 管理员 | 编辑证据、场景、素材、权限与活动配置 |

## 3. 核心流程

1. 管理员建活动，导入EV-001至EV-025及VR/AR节点。
2. 配置热点、关联证据、开放阶段、角色权限、媒体与GM备注。
3. 玩家加入小组，扫码调查并取得证据。
4. 多个渠道取得同一EV编号时去重，来源各自留档。
5. GM推进阶段，关键线索必要时保底开放。
6. 小组提交庭审五问，按8分制评分；终局投票独立记录。

## 4. 功能需求

| ID | 模块 | 描述 | 优先级 | 验收条件 |
|---|---|---|---|---|
| D-01 | 证据管理 | EV唯一编号；编辑玩家正文、GM备注、媒体、来源、关联证据、解锁阶段 | P0 | 25条证据可导入检索；重复ID阻止保存 |
| D-02 | VR热点 | 场景图/全景及热点编辑，热点绑定证据 | P0 | 6场景可配置和预览 |
| D-03 | 玩家证据库 | 多渠道取得同一EV去重，来源可追溯 | P0 | VR与实体渠道不生成重复证据 |
| D-04 | 权限阶段 | 玩家/NPC/GM/管理员分权；条件或GM手动解锁 | P0 | 未解锁内容及GM备注不能从玩家端读取 |
| D-05 | AR二维码 | 固定二维码路由到六个节点；支持静态/3D降级 | P0 | 无AR设备仍可读同等剧情信息 |
| D-06 | 主持台 | 阶段、证据解锁、小组进度、保底开放及操作日志 | P0 | GM可保底公开EV-007并留日志 |
| D-07 | NPC证言 | 按角色可知事实与阶段呈现 | P1 | 演员端看不到全局真相 |
| D-08 | 庭审评分 | 提交凶手、死因时间、录音诡计、密室、动机并按8分评分 | P1 | 终局价值投票与案件评分分离 |
| D-09 | 离线降级 | 打印证据/静态图备份；故障时继续推理 | P0 | 核心真相不依赖AR或单点网络 |
| D-10 | 导入导出 | 支持证据/场景Excel或CSV导入与备份 | P1 | 错误行可定位；关系可还原 |
| D-11 | 媒体管理 | 图片、音频、视频、GLB模型和版本管理 | P1 | 替换媒体不变更EV编号 |
| D-12 | 移动端 | 手机扫码、30—40人和至少6组并发设计 | P0 | 主流iOS/Android浏览器可浏览并有失败提示 |

## 5. 推荐数据结构

### Evidence
`evidence_id`（唯一稳定EV编号）、`title`、`category`、`summary`、`player_content`、`gm_note`、`source_type`、`scene_id`、`hotspot_id`、`ar_node_id`、`unlock_phase`、`unlock_condition`、`allowed_roles`、`fallback_phase`、`asset_ids`、`related_evidence_ids`、`is_critical`。

### Scene / Hotspot / AR Node
Scene：`scene_id`、名称、背景素材、开放阶段；Hotspot：`hotspot_id`、场景、位置、交互类型、绑定证据、条件；AR Node：`ar_node_id`、二维码ID、替代页、模型素材、调查步骤、发放证据。

### Acquisition Log
活动、小组、证据ID、获取来源、时间、主持人操作标识。证据按ID去重，来源保留多条。

## 6. 固定剧情规则及边界

- 凶手伊芙琳；索恩约20:58遭奖杯致命袭击；21:07为预录ECHO语音；安全通行20:51—21:02；动机涉及莉娅数字人格。
- EV-021只支持死亡时间估计，不单独精确判定医学死亡时刻；纤维物证须与其他证据组合。
- 拍卖仅给先机；EV-007等关键证据设置后期保底开放。骰子不改变真相、不永久阻断关键线索。
- AR不可用提供静态图/3D旋转降级；断网提供纸质线索包。
- 21:07音频、21:09自动回复、门禁和舞台照片使用同一活动时钟。
- 玩家端不得通过接口、缓存或前端数据访问未解锁正文、GM备注与真相。

## 7. 非功能要求

手机浏览器优先、扫码免安装；按30—40人/至少6组并发设计；操作与解锁有审计日志；媒体可替换但证据ID稳定；导入错误可定位；不采集无关个人信息。涉及相机时说明仅用于扫码/AR。

## 8. 分期建议

- **P0可开场：**证据/热点管理、二维码跳转、玩家证据库、阶段权限、GM控制台、保底开放、打印/降级。
- **P1增强：**分阶段AR鉴定、NPC证言、庭审评分、媒体版本、导入导出。
- **P2沉浸升级：**空间AR锚定、3D物件交互、实时进度可视化。

## 9. 验收用例

1. 导入25证据；重复ID报错且定位到行。
2. VR和实体渠道取得同一证据只显示一份，来源均可追溯。
3. 玩家无法读取未开放证据及GM备注。
4. 六二维码到达固定节点；不支持AR仍显示同等信息。
5. GM保底开放EV-007后记录操作并对玩家显示。
6. 核心网络故障时打印版仍可完成推理。
7. 庭审评分：凶手2、死因与时间1、数字语音2、密室1、动机2，共8分；终局价值投票单独处理。
