# 阿拉斯加之夜：最后的遗嘱

根据用户提供的TRPG策划V2构建的本地全栈首版。React响应式玩家页面 + GM导演后台 + NPC任务页面，Express服务端 + PostgreSQL持久化数据库（本地开发可使用SQLite）。当前项目为单场活动。

## 运行

需要Node.js 22.13+（已在本机Node 26.3测试）。

```sh
npm install
npm run dev
```

打开 http://localhost:3000 。玩家入口 `/play`，免登录 AR 搜证入口 `/ar`，管理入口 `/admin`。首次启动生成 `.env`，工作人员密码随机生成，不包含默认公开密码。

```sh
node scripts/credentials.js
```

这个命令仅在可信终端显示管理员口令及NPC手机号绑定状态。管理员账号为 `admin`（兼容 `gm`）；NPC登录手机号由管理员在内容管理中心绑定，不再使用密码。`.env`不提交版本控制。

```sh
npm test
npm run build
npm start
```

开发与生产均为同源API和HttpOnly Cookie会话。默认仅监听127.0.0.1；如需局域网测试设置 `HOST=0.0.0.0` 并在手机使用本机局域网IP地址。二维码基于当前访问域名生成，localhost二维码无法被其他设备访问。

## 已实现

- 公开活动首页、四幕介绍、六NPC公开档案、最多50人报名，GM可调低容量与调整门票参考价。
- 玩家手机号验证码注册/登录，首次验证自动报名；NPC由后台绑定手机号后验证码登录，仅管理员保留密码。验证码15分钟有效、一次使用、发送限频及错误锁定，7天HttpOnly会话。
- 报名后专属邀请二维码；扫码仍要求登录对应玩家账号，二维码不承担永久鉴权。
- 已付款宾客可在「我的角色」生成双面角色卡：点击后 AI 提炼20字标签、72字故事与两条短目标，正面保留大幅肖像和身份，背面展示摘要与专属登录二维码。支持翻面预览、正反面高清 PNG 和半 A4 双面 PDF；GM 可勾选合排 A4，每张两位，正反逐页配对。二维码可重置，退款后不可扫码登录；完整故事折叠保留。
- 万圣节 Cos 角色、原作来源、玩家故事与头像填写；OpenAI 兼容大模型生成庄园背景、2–3 位 NPC 的双向关系和分幕互动目标，未配置时明确使用模板草稿；提交并完成剧情生成后自动审核通过，对应 NPC 可查看关联玩家。隐藏同伙最多3人，不随机分配。
- GM人工核验票务、幂等签到并发放3枚初始金币、调查组分配。
- NPC只能完成自己名下委托；首次完成记账发奖励，重复请求不重复领奖，第一幕自动奖励累计上限10金币（含签到）。
- 金币流水、GM金币调整、多人联盟集资的人工账本操作；余额不可负或低于已有竞拍预留额。
- 六件拍品、实时轮询竞拍价、领先竞拍余额预留、GM落槌、单次成交和背包发放。
- 十二张核心证据种子、现场二维码、内置相机扫码/图片识别/编号入口、密封卡翻牌、永久证据册；独立 `/ar` 页面免登录查看扫描线索的基础文字与三个本地剧情 GLB 模型，提供空间标题、扫描光环和可暂停的原创氛围音乐。GM 可在「证据与二维码」下载全部证据二维码 ZIP 或单张 PNG。游戏内进阶信息与证据册仍按玩家权限读取。
- 基础证据第三幕取得，额外细节由服务端D20结果决定；每组每区仅一次主要鉴定，技能匹配+2，自然20自动取得进阶信息。
- 四幕切换、全场广播、玩家12秒/后台8秒轮询、GM紧急放行、证据内容和NPC背景编辑。
- 终幕道具使用登记（一次性）与GM现场执行；最终嫌疑人、动机/手段/机会三证、结局选择及投票统计。
- 全部工作人员操作记录，GM/NPC/玩家数据权限分离。

## 当前范围与待接入

**支付**：当前为线下付款 + GM人工核验，没有接入微信/支付宝支付、自动退款或短信。

**人物生成**：支持 OpenAI 兼容的服务端 `chat/completions` 接口。配置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 后自动生成；支持 JSON Schema / JSON Object 两种输出模式并二次校验。未配置时为明确标记的模板草稿，服务调用失败时保留输入并允许重试，角色提交并完成剧情关联生成后自动审核通过。完整配置和剧情设计见 [docs/ROLE-STORY-AND-XR.md](docs/ROLE-STORY-AND-XR.md)。

**剧情**：采用策划方案的六NPC、四幕与十二张关键证据，证据措辞为开发种子，尚未完成精确分钟级时间线和36份独立角色剧本。需活动前由策划定稿。NPC已配有六张档案立绘。

**庭审**：道具效果由GM在现场执行。命运重掷券当前登记使用后需GM现场裁定，系统不自动进行额外重掷。最终胜负也由GM审核三项证据和附加目标后裁定，统计页面不自动宣判。

**扫码**：独立 `/ar` 页面无需注册、付款、签到或等待剧情阶段。点击开启全屏相机，模型持续贴合现场二维码的位置、方向、大小和透视；二维码在墙上时，模型底面贴墙，厚度朝外。模型覆盖码面与白边，轻触可拆信、启动终端、开合物证箱。连续特征追踪与防抖缓解闪烁，短暂掉帧保持显示，持续丢码淡出，重新对准恢复。文字线索在相机内展开，360°预览和图片/编号阅读收在次要入口。后台二维码使用 `/ar?clue=E-01`，站内兼容旧 `/play?clue=...`；系统扫一扫预载线索后，点击开启相机对准原码。游戏内解锁、D20进阶鉴定和证据册仍检查玩家资格与阶段，匿名扫码不写入个人数据。相机需要 HTTPS 或 localhost 及授权；图像只在设备本地识别，关闭、返回和切后台会停止相机。定位约定与实机边界见 [docs/QR-TRACKING.md](docs/QR-TRACKING.md)。

**运营**：单场活动。生产使用现有 PostgreSQL，按日执行数据库备份；本地未配置 `DATABASE_URL` 时使用 `data/alaska.sqlite`。广播为轮询；无密码找回、短信验证和多人转账事务。联盟集资先使用GM人工账本调整；正式运营前应添加批量集资流程。

## 部署配置

生产部署使用 Docker，仅运行应用容器，连接服务器已有的 PostgreSQL，不创建数据库容器。部署、备份、更新和回滚见 [deployment/README.md](deployment/README.md)。

`.env` 中设置 `DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE` 即可启用 PostgreSQL；不要将真实连接密码提交到代码库。连接池最多 3 个连接。首次启动创建数据表并填充缺失种子，重启不会覆盖 GM 编辑。修改 GM/NPC 主密钥时还应清空 sessions 表，使旧工作人员会话失效。

```sh
# 在具有创建测试 schema 权限的数据库上运行 PostgreSQL 集成测试
TEST_DATABASE_URL='postgresql://USER:PASSWORD@localhost:5432/DATABASE' npm run test:postgres
```

测试在随机独立 schema 中运行，验证完成后删除测试 schema，不写入生产 public 表。覆盖完整玩法、数据持久化、事务回滚以及两个应用实例并发报名、签到和拍卖结算。本地 `npm test` 使用独立 SQLite 数据库。

## 目录

`src/`：页面、交互与样式。`server/content.js`：NPC/证据/拍品种子。`server/db.js`：数据库适配入口与本地SQLite结构。`server/postgres.js`：PostgreSQL结构与事务。`server/app.js`：鉴权与规则引擎。`tests/api.test.js`：独立内存数据库集成测试。`DESIGN.md`：视觉和内容约定。

技术资料：[Node SQLite](https://nodejs.org/api/sqlite.html)、[Vite](https://vite.dev/guide/)。

## AR / VR

顶部「AR搜证」打开免登录独立页面 `/ar`，默认全屏相机持续追踪二维码，无需 WebXR 或另印定位海报。「360°预览与沉浸观察」是次要入口，可环绕、缩放证物或打开带标题、编号、定位光环和粒子的 Three.js 场景。该预览内仍保留 WebXR 自由放置和 Android Scene Viewer / iOS Quick Look，不承担二维码锚定。公开页面音乐在用户操作后启动，支持音量调节和暂停，切后台暂停、离开页面释放音频资源。

玩家页面保留「我的角色 / AR搜证 / 证据册」三个游戏入口；「360°查看证物」放在证据册中，头显入口默认折叠。首次建角色只需头像、Cos角色、来源和故事，其他设定可选。鉴赏入口提供已解锁模型的旋转、缩放、全屏与可选头显 VR。HTTPS、浏览器和实际设备能力决定 AR / VR 是否可进入。当前为三类证物示例，不含真实庄园全景或多人虚拟空间。资源替换、权限与设备验证见 [docs/ROLE-STORY-AND-XR.md](docs/ROLE-STORY-AND-XR.md)；历史评估见 [docs/WEB-VR-ASSESSMENT.md](docs/WEB-VR-ASSESSMENT.md)。

## Web AR 搜证重构

管理员入口 `/admin` 支持账号 `admin`（兼容 `gm`，使用原GM密码）。新增内容管理中心，覆盖报名资料与名单导出、完整角色卡、线索、NPC、委托、拍品、广播、AR场景及首页文案。配置持久化到数据库，AR配置保存后即时生效。功能及权限边界见 [后台操作说明](docs/ADMIN-OPERATIONS.md)。

新增独立证据领域模块和 AR 场景/热点 API，复用现有玩家资格、剧情幕数及证据册。纸页、墙面和区域图像锚点采用同一场景配置，资源域名可在同源、OSS和CDN之间切换。当前已接入摄像头图像定位、真实GLB证物柜、热点点击、3D预览及打印海报；正式房间模型与现场标定需按实际布景制作。墙面定位、空间跟踪边界、OSS/CDN性能与后续实施见 [Web AR 架构方案](docs/WEB-AR-ARCHITECTURE.md)，场景配置见 [示例JSON](docs/ar-scenes.example.json)。

默认提供 `/ar/demo` 公开体验、`/ar/wall-study` 正式搜证及 `/ar/target` 定位海报。可设置 `AR_SCENES_FILE` 覆盖正式场景，`AR_ASSET_BASE_URL` 切换资源域名。现场操作、测试与发布见 [AR操作说明](docs/AR-OPERATIONS.md)。

## 线索配乐音频

26条证据的基础/鉴定说明及6个AR节点已配音，共58段。扫码后对应3D模型的AR操作区提供播放按钮，主页面不显示线索播放器；玩家已打开的线索卡及物证弹窗也可聆听，支持暂停、继续、重播与错误重试；播放期间原氛围音乐临时暂停。鉴定录音沿用文字权限，GM修改正文后隐藏旧配音。原二维码不变。

媒体放在`server/audio/files`并由受控接口提供，不要映射为公开静态目录；发布包须包含整个`server/audio`。角色语音使用MiniMax固定系统音色，配乐采用下载的CC BY4.0作品，播放器内提供署名。制作、权限与验收见 [线索音频说明](docs/CLUE-AUDIO-20261015.md)。
